# 桌面调用与验证范围

## 桌面调用

安装`工具/桌面推理依赖.txt`中依赖后，可直接使用Python参考程序，不需要原.pt或PyTorch：

```text
python 工具/预处理与推理.py --assets assets/肉类新鲜度 --input 你的输入.json
```

输入JSON格式：

```json
{
  "meat": "猪肉",
  "temperature_c": 25,
  "pixel_state": "corrected",
  "rois": {
    "C11": "已矫正像素/C11.png",
    "C12": "已矫正像素/C12.png",
    "C13": "已矫正像素/C13.png",
    "C21": "已矫正像素/C21.png",
    "C22": "已矫正像素/C22.png",
    "C23": "已矫正像素/C23.png",
    "C31": "已矫正像素/C31.png",
    "C32": "已矫正像素/C32.png",
    "C33": "已矫正像素/C33.png"
  }
}
```

ROI路径相对输入JSON所在目录解析。原始ROI则pixel_state填raw，并增加gains对象：C11到C33每个区域各自一个[gain_r,gain_g,gain_b]数组，填写上游实际增益。corrected输入不再提供gain，以免重复应用。没有提供真实照片示例或编造增益值。

## 本次实际验证

- 7个图通过onnx.checker完整结构检查、ONNX Runtime CPU加载；权重全内嵌，没有外部张量数据文件。
- 公共前端以全0、全1及固定随机RGB输入比较PyTorch与ONNX特征。
- 6个双目标模块均以这3种输入做完整链路PyTorch/ONNX比较，包括猪肉两个工况；图中单位恢复和时间Softplus一并比较。
- 牛肉25 ℃的103张、4 ℃的117张完整保留测试图，从当前原始ROI、实际增益重新生成像素，核对参考预处理与原项目逐像素相同，再将ONNX预测与存档结果对比。
- 鸡肉25 ℃的68张、4 ℃的84张完整测试集，使用哈希与原核验记录一致的冻结前端张量比较ONNX模块输出与存档预测。它不是本次鸡肉原始像素端到端测试。
- 以上372张测试输入、744个目标预测的最大差异：TVB-N约0.0000205 mg/100 g；时间约0.0001624 h。精确逐图数值见核验JSON。这是导出运算误差，不是模型相对实测标签的RMSE。
- Kotlin缩放算法的Python数学镜像与当前Pillow在22组缩放组合、两种完整合成输入上逐像素一致；两种输入的各工况结果保存在随包自检JSON。

本次真实预测比较接受阈值TVB-N为0.003 mg/100 g、时间为0.02 h，实际误差远小于阈值。合成导出比较另有相对误差阈值，详细记录见初检JSON。

## 未覆盖的验证

猪肉与鸡肉原ROI目录已不在原D盘路径，未替换、搬移或另行映射。猪肉没有新做真实照片端到端ONNX验证；鸡肉使用原先核验的冻结张量。原检查点及全部对应关系均通过SHA256校验。

本机没有JDK/Kotlin编译器、APP工程或目标手机；未编译Kotlin、构建APK或进行真机性能/内存测试。请在实际工程先运行包内MeatDeploymentSelfCheck。若APP的原图颜色空间、ROI裁切、校正、缩放或执行提供程序变化，仍应重新检查数值一致性。

## 复现导出

包内`工具/导出与核验.py`是本次实际使用的恢复与导出源码。它需要原项目的`work/交接模型只读清单.json`和清单指向的13份原始.pt（公共预训练1份＋任务12份），并按SHA256核对；仅用于再次导出，运行APP不需要这些源文件。

```text
python 工具/导出与核验.py --inventory 原项目/work/交接模型只读清单.json --output 新输出目录
```

工具不进行训练。PyTorch官方使用说明：[torch.onnx（2.10）](https://docs.pytorch.org/docs/2.10/onnx.html)。像素缩放数值定义参考[Pillow滤波实现](https://github.com/python-pillow/Pillow/blob/main/src/libImaging/Resample.c)，实际对照版本为本环境Pillow12.3.0。
